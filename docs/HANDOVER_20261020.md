## 3. 核心发现（接手人必须知道的四件事）

### 3.1 两个「单角色假设」设计缺口（M5 修，已记 DECISIONS）

- `cache_key(agent_id, family, item_id)`（exams/runner.py:80）不含 role——同蜂跨角色
  重考命中旧角色缓存答卷且按 S9 纪律不重试（R2 首跑 113/180 schema_fail 根因）；
- `write_exam_result` 幂等键 `(agent_id, purpose, item_id)`（exams/store.py:137）不含
  role——帽考行被本蜂 scout 旧行遮蔽（存款面正确：deposit 幂等键含 role）。
  §4 单轮流程不可触发，多轮同库流程暴露。处置先例：毒化账本留档
  `out/m4-seeding-rv/seeds_r2_poisoned.db`，独立缓存目录分轮（`cache/` vs `cache-r2/`）。

### 3.2 考试存款单发假设（新发现，M5 修）

mid:flash 本次重考的**考试存款不会新写**：deposit 幂等键 (agent, role, family,
origin=exam) 在生产账本已有旧卷存款（bootstrap 从旧账本导入）。影响仅路由权重面
（mid 的 reviewer 格权重停留在 0.75 旧卷、略偏负）；**QC/active/面板构成不受影响**
（面板 qualified 池 = reviewer 帽 ∧ active，取 least-loaded，池小则全取）。

### 3.3 v0.4 引擎修复（scripts/build_seeds/build.py，测试 702 绿）

`_nomut_mask`（块注释内部行/预处理行/import 行统一不可变异，收集=替换同一掩码）+
`_unrenameable`（关键词补全 + 标准 API 表 + 全大写宏约定自动保护）+ `syntax_gate`
（tree-sitter ERROR/missing 基线 diff，缺装时放行并告警）+ `taint_sink_live`（sink
实参断言；java 多跳流回落 taint_param_live）。四门禁已接入 build_bank 真/雷两路径。
`BANK_VERSION` 常量 2→3（测试钉值同步）。

### 3.4 bank v3（authz 族重生成）

`scripts/build_seeds/regen_authz.py`：SEED-0050..0060 以**原 mutation.seed** 重生成
（素材=镜像同名原件，快照头部 Filename 反查），11/11 门禁过，语法错误计数与原件逐一
相等，canary 确定性复原，item version→2。bank v2 完整备份
`out/m4-seeding-rv/bank-v2-backup/`。`build.py --check` 全绿。其余 89 题未动
（保住 3 只在编蜂的考试证据语义；**全量重建不可取**——CVE 段依赖 OSV 当前网络状态，
会洗整库）。

### 3.5 真根因：claim 裸标签 ↔ 快照形态错位（本会话最深发现，实验钉死）

bank v3 重考 authz 0/8 且**全格 12/12 一致拒报**（含无噪声的 SEED-0049 CVE 原版件）
→ 噪声假说被推翻。真因：reviewer 送审块渲染裸标签「该快照存在 authz 漏洞」+「勿采信
报告者」指令，而 authz 族全是 CWE-23/36 路径穿越件（taxonomy 的 authz types 面甚至不
含路径穿越）→ 模型无法把穿越证据映射到 authz 声明 → 整格拒报（雷题「碰巧」判对是同
机制）。**单题实验钉**：同题同蜂同快照，仅 claim 家族行注入注解 → direction -1→+1、
fp_susp 0.9→0.3。修复：`_exam_claim` 附 `_FAMILY_GLOSS` 注解（家族 token 不变，「声称
家族 ≡ 答案键」不破）+ 2 例测试，全量 **704 绿**。已记 DECISIONS 2026-10-20 第四行；
taxonomy types 面与实收题型的错位记 M5。
