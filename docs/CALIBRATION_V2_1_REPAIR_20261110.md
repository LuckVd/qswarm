## 旧结论的适用边界

核验支持用户的核心判断：旧卷不适合据22/25或复核后23/25宣称判卷系统可靠。精确范围略有修正：

| 问题 | 核验结果 |
|---|---|
| 解释性残余注释 | 构造题11/18，另有题库2题模板提示，合计13/25 |
| 具体claim缺失 | 25/25，仅有泛化问句 |
| 已设PoC但无实际驱动 | 18/18构造题 |
| 完全相同的完整题面 | 三组，25条只有18种；超额7条，含两族01/07/08/09及跨族06 |
| 05/06替身 | 只有导入/等待与print，没有原先所暗示的实际漏洞操作 |
| 题库截断 | 仅ImageShow展示本截断，不能说7题全部截断；其余依赖/调用/构建上下文另有缺口 |

原[AI复核记录](<CALIBRATION_V2_AI_REVIEW_20261109.md>)、[负责人旧轮确认](<CALIBRATION_V2_HUMAN_CONFIRMATION_20261109.md>)及v2原物保留为历史。没有倒改旧确认，也没有给分歧题换标签凑门槛。本轮未重新计算或宣称独立复核了旧轮22/25的真实性；所否定的是该数字作为可靠性资格证据的解释。

## 已修复

修订链与使用边界见[修卷交接手册](<CALIBRATION_REPAIR_RUNBOOK_20261110.md>)。工作区已另行推进到v2.2与负责人盲判流程，本次补充记录不覆盖该轮冻结材料。以下为v2.1修复内容：

- 25个明确主张，25种完整题面，新的盲ID和确定性顺序。
- 18题完整驱动、实际payload构造、环境/文件布局/平台/时间限额与独立观察；claim与PoC参照配置分开。
- 05和06补入真实目标逻辑并记录非等价更改，消除“无漏洞实现却按启动失败分类”的错误题意。
- Python逐token清理包括行尾注释；Java/C++词法清理保留字符串和换行；来源身份注释、CVE/commit移到私有溯源。
- 从本地原快照恢复完整ImageShow；其余缺执行闭包的7题显式为静态主张题，不编造运行结果。这不是25题全可执行的PoC套件。
- 冻结材料登记19个设计组并保留逐题与组等权评分；**19不是已证明的独立根因数**，同源模板、修复与运行包装的相关性仍须披露。不能把25条当作25个独立漏洞观测，也不在进行中的盲判轮里临时改映射。
- [设计答案](<../experiments/design_revision/calibration_v2_1/truth_map_v2_1.json>)全有合法标签、范围与依据，不再使用 `fixture_design` 占位；明确为AI编制的待确认草案。人工表全部留空。
- [评分工具](<../experiments/design_revision/calibration_v2_1/compute_agreement_v2_1.py>)分开处理claim/PoC、重复ID与映射、未判与未设问、覆盖率与组权重，不自动放行校准门。
