# qswarm 设计调整与验证方案

日期：2026-10-22  
状态：**建议稿，供负责人批准；不是已生效 SPEC，也不是实施完成报告。**  
依据：当前 M5 实现、M4/M5 联调报告与本次设计复核。本文只提交方案，不改变生产配置、历史账本、题库或考试纪律。

## 0. 结论与决策摘要

建议继续，但改变推进顺序：**先证明有稳定专长，再证明路由能利用专长，最后完善组织生命周期。**

保留已有的分级检测流水线、确定性内核、工件库、沙箱、预算控制、根因聚类与可重放账本。暂不扩建自动晋升、弹性编制、组织展示等功能。把下一阶段目标从“完成自进化蜂群”改为：

> 在未参与调试的仓库上，相同预算下，历史反馈驱动的调度是否优于固定调度；若没有优势，系统能够退回更简单的固定级联，而不损失已有工程资产。

核心改动：

1. 分开 **运行资格、检测判断、学习证据**，不再让“有帽子”“获得投票”“产生存款”隐含能力已被证明。
2. 以 **模型与执行策略配置** 为学习对象，agent_id 只作为执行身份；等价副本不作为独立专家。
3. S1 保留会诊功能，但在新实验策略中默认只影子记账，不给能力排名提供直接奖励。
4. 为漏检建立独立观察渠道；没有评估的数据记 unknown，不当负例，也不从分母里悄悄删除。
5. 事件账本继续 append-only；另建可重建的有效证据视图，让纠错替代旧判断而不增加独立样本数。
6. 把 S2 的“脚本执行成功”与“漏洞主张获得可信验证”分开；加入修复版/安全版负对照。
7. 先做固定卷、同预算、跨仓隔离的对照实验；只有结果支持时才启用真实自适应派单。

**不建议现在做的事**：直接替换路由算法为更复杂 bandit、降低 QC 线、反复抽卷直到过线、全量推翻旧账本、为了换名称重新实现全部模块。

## 1. 问题依据与结论边界

### 1.1 已确认的事实

| 事实 | 依据 | 对方案的影响 |
|---|---|---|
| 角色派单只检查帽与本体 active，未检查角色 QC | `qswarm/kernel/consult.py` `_active_by_role`；`qswarm/kernel/verify.py` | 资格门禁先修；不能靠人工不运行 smoke 维持隔离 |
| 帽在考试前注册，帽考失败不降编本体 | `qswarm/exams/seeding.py`、`roster.py` | 要区分本体状态和角色资格，包括未考/中断状态 |
| QC accuracy 是真题正确数/真题数 | `qswarm/exams/seeding.py` `_qc_record` | 报告明确 real_recall，并列 FP 拒判；是否改变门槛另行决策 |
| 两次 verifier 考试为 31/40 与 29/40，FP 拒判为 14/20 与 16/20 | `out/m5-e2e/exam-{engineering,strong-hat}/seeding_report.json` | 不能把 QC 分数当总体准确率 |
| 两卷 seed 相同但 agent 不同，题目只重合 38/60 | `qswarm/exams/paper.py` 派生种子含 agent_id；两份 JSON 题目集合对账 | 不能用两次分数差估计同卷波动或断定能力上限 |
| 当前 cells 的 n_eff 定义为 2×权重和 | `qswarm/kernel/cells.py`、`contracts/schema.sql` | 保留为旧版积分，不能直接解释为独立样本数 |
| 现有离线 S2 试跑 2/2 来自模板、process 档 | `out/m5-trial/verify_report.md` | 只证明局部执行链，不证明真蜂生产链与泛化效果 |
| 命令注入模板用输出中出现 marker 判断触发 | `qswarm/sandbox/pocgen.py` | 存在回显混淆风险，需负对照；本次未执行误判复现实验 |

M5 最新真蜂结论以 `out/_m5_final/M5_E2E_INTEGRATION_20261021.md` 为入口，但其中“两蜂同卷”“能力边界”等强推断需要补充勘误。现有 754 passed 是交付报告记录，不是本次重新执行的结果。

### 1.2 尚未证实的设计假设

- 不同蜂具有跨任务、跨时间稳定的专长差异。
- S1 共识对未来真实正确性提供独立增量信息。
- 生产口碑能够预测后续未见任务的表现，而非只记录历史任务难度。
- 多蜂系统在同预算下优于一个强模型或简单固定级联。
- 可验证漏洞的反馈能够代表全体漏洞，而非只代表容易复现的子集。

上述是实验对象，不是本方案预先断言其成立或不成立。

## 2. 改后的架构与边界

```text
仓库/变更
  → L0 候选生成 → L1 侦察 → L2 审查/会诊 → 根因聚类
                                            → S2 验证 → 人工复核
       │ 每层保留去向、拒绝与预算截断记录           │
       └──── 独立抽查与已知答案评测 ───────────────┘
                                                   ↓
原始事件/工件（不变、可审计） → 有效证据视图（可纠正、可重建）
                                                   ↓
                                   影子策略评估 / 时序对照
                                                   ↓
                                   获批后才驱动下一批路由
```

生产路径继续服从原有权限、预算与单写口。实验路径使用独立账本和命名空间，不自动导回生产 cells。抽查不绕过沙箱/资格门禁，也不突破总预算。

三个概念必须独立：

| 概念 | 回答的问题 | 允许影响 |
|---|---|---|
| Qualification | 这个配置是否被允许执行这个角色？ | 派单资格、安全限制 |
| Finding verdict | 这个具体漏洞主张是否成立？ | 报告等级、该事实的有效证据 |
| Capability estimate | 这个配置在某类未来任务上的预期表现如何？ | 实验排名；批准后的路由 |

入职考通过不等于专长已证实；角色资格失败不等于蜂其他角色全部失效；一次 S2 结论不能给 verifier 自证能力加分。

## 3. 工作包 A：角色资格与配置身份（先做）

### 3.1 身份模型

保留现有 agent_id 和旧外键，新增两类身份，不在第一轮重命名历史主键：

- `execution_profile_id`：执行配置的规范化哈希，涵盖 provider、请求模型、角色、prompt 内容哈希、工具/上下文策略版本、contract、采样参数。
- `qualification_policy_version`：资格判据版本；考试数据版本和卷 ID 单独留档。

运行记录另存 provider 返回的 served model/version、原始响应身份字段和观测时间。供应商不披露时写 unknown，不能由请求名推定真实底模不同。身份不明时不主张异构性，也不把未确认路由变更算成新专家。

同一 profile 的多个 worker 只代表并发副本，学习数据汇总到 profile，不因 worker 数增加样本量或独立投票数。不同 prompt 的 profile 可视为不同策略，但不自动视为错误独立。

### 3.2 资格记录与状态机

拟新增 `role_qualifications` 可重建投影，键为 `(agent_id, role, execution_profile_id, qualification_policy_version)`，保存：

- `status`: pending / passed / failed / stale / revoked；
- `exam_run_id`、bank_version、paper_id、判分策略版本；
- 通过/失败指标与时间、失效原因、对应事件序号；
- 被替代资格引用，避免多条并存时随意选到旧 passed。

规则：

1. attach_hat 只声明角色，不能授予执行资格。
2. 首次考试及强制重认证先写 pending；调用中断、参数校验失败不能留下 passed。
3. 纯诊断测评与资格考试分开：诊断不改变资格，避免任意试验使生产身份掉线。
4. 正式考试成功原子性写结果与资格；失败只影响对应角色。
5. profile 改变后旧资格不得自动沿用；未知供应商漂移通过抽检/定期重认证处理，不能假装本地可完全检测。
6. 生产 verifier 选择必须满足本体 active、帽存在、当前 profile 对应资格 passed；在最终 dispatch 前再检查，阻断排队后被撤资格的任务。
7. 报告拆成 `agent_status` 与 `role_qualification_status`，不再用考试计算值冒充数据库本体状态。

**存储纪律**：资格状态由考试模块既有写口负责，生产读取；新增审计事件/物化投影需在 SPEC-1/6 和写口审计白名单中明确，不允许脚本直接更新。

### 3.3 历史迁移

- 旧本体/帽/考试/存款不删除。
- 迁移先 dry-run 输出清单；只有能确认 profile、角色、完整考试证据与适用判据的记录才可导入 passed。
- 无法证明者为 stale/unknown（投影状态统一用 stale，reason=legacy_unverifiable），不得通过已有帽或正 cells 反推合格。
- 先对 verifier 强制生效，再盘点其他角色；逐角色启用计划写入迁移 manifest，避免无意让全系统突然停摆。
- 回退应用版本时不得回退成宽松生产派单：保持外围暂停验证写入，直到恢复资格门禁。

### 3.4 验收

未考帽、失败帽、中断帽、旧 profile passed、排队后 revoked 均不调用模型、不执行 PoC、不产生 verdict 存款；合格帽正常执行。某角色失败不改变其他角色。并发考试/资格更新不得使旧结果覆盖新资格。

### 3.5 启动就绪条件按执行拓扑检查

现有 M4 联调使用 4-active 地板，`run_verify` 也调用 `verify_ready`。新的单模型基线若复用这些入口，不能为了满足编制人数而注册假蜂。

建议把实验入口的 readiness 改为阶段能力检查：该实验臂所需角色/工具是否具备、执行 profile 是否合格、预算是否就绪、沙箱档位是否正确。一个 profile 可以执行多个已获资格的角色，但需要独立评审的实验臂仍遵守报告者不能自评的规则；单模型自检属于不同实验臂，报告中不得称为独立复核。在独立实验入口先实现这一规则，修改生产固定人数门槛需另行修订 SPEC，不能借做 baseline 静默绕过生产门禁。

## 4. 工作包 B：拆开弱共识、证据与能力积分

### 4.1 不重写旧 cells，新增策略版本

现有 cells 和 M0 黄金结果保留 `legacy_v1` 语义。新增实验策略 `evidence_v2`，第一版只生成文件投影，不增加生产表；确认确有使用价值后才考虑物化。

建议新增：

- `qswarm/kernel/evidence.py`：纯读取事件与工件，解析有效证据；
- `qswarm/evaluation/`：实验 manifest、任务匹配、统计、报告；
- `evidence_v2.jsonl`：可重建证据视图；
- `capability_v2.json`：按 profile/role/family 汇总，不立即参与派单。

这不是把原 n_eff 换个名字再套 Wilson；旧参数与新指标不可直接互换。

### 4.2 最小证据结构

每条学习观察记录以下字段：

| 字段 | 用途 |
|---|---|
| observation_id / logical_evidence_id | 某次观察与同一逻辑事实的稳定键 |
| root_cause_group_id / repo_commit / task_id | 去重、聚类、时间顺序与跨仓隔离 |
| execution_profile_id / role / family | 归属对象 |
| claim / decision / truth_label | 模型输出与外部真值分开；真值可为 unknown |
| truth_source / oracle_version / adjudication_ref | 区分测试判据、人工判定、已知答案、S1 共识 |
| eligible_set / selection_probability / selection_reason | 记录观察如何被选中，不伪称无偏样本 |
| occurred_at / available_at | 事件发生与真值可用时间，防止延迟反馈穿越 |
| supersedes / correlation_group | 纠错与相关性分组 |
| cost / latency / failure_kind | 质量以外的成本与工程可用性 |

任务真值、针对该任务的各策略输出、基础设施失败分别记录，不把无标签记录转换成判错或判对。

### 4.3 纠错规则

账本只追加不变；有效视图不是简单把正负记录全部累加。

- 同一逻辑事实的纠正追加 `supersedes` 指向旧记录；有效视图只保留当前适用判断。
- S3 推翻 S2 后，一个根因仍只贡献一个事实单位，不凭纠错增加独立样本数。
- 高层级不等于永远正确：两次同级冲突或人工不一致，先标 disputed，待独立裁决，不默认最后写入者胜出。
- 同一根因有多个报告者，各报告者可以各获得一次归因；同一 profile 对同一根因不因重复 finding 获得多次能力样本。
- root cause 不确定时保留 provisional 分组，报告去重敏感性；不能把旧 cluster_id 自动当跨运行真值键。
- 历史数据若不能恢复可靠逻辑键，不猜测补齐：仅作 legacy 描述，不进入新策略确认性分析。

### 4.4 能力指标与 S1

分别输出：

- 已知正例召回、已知负例拒判、报告 precision（有可靠真值时）；
- 未标注/未验证覆盖率、schema 合规、基础设施成功率；
- 去重根因数、仓库数、样本来源分布；
- 单任务成本、确认一个独立真漏洞的成本。

有金标准的定位任务：只有真实漏洞落在分配给该策略的可观察范围内，才可把未报告记为漏检；超出上下文或预算未执行要单列，并在系统级召回中保留预算损失。

上报指标按根因去重后列 TP/FP/U，disputed 归 U。有标签 precision = TP/(TP+FP) 只是条件指标；同时给出全量上报 precision 的未知标签界限 `[TP/(TP+FP+U), (TP+U)/(TP+FP+U)]`，分母为 0 记不可估。这是未知标签造成的范围，不是统计置信区间。不同策略标签覆盖不同时，不能仅凭条件 precision 判定非劣；正式实验应完成统一盲审，或预登记保守界限/缺失敏感性判据。将错误移入 unknown 不得形成上线优势。

新策略默认：S1 继续用于会诊筛选、解释和影子信号，不进入 capability 排名与晋升；S2/S3 也必须满足新 oracle/证据规则才成为学习标签。旧 S1 账本不删除。

S1 是否重新加入路由由消融实验决定。不得仅凭 S1 与 S2 表面一致率高宣布有效，需检查共同错误与验证选择偏差。

### 4.5 验收

同事实重复投票、重复 finding、重放、补偿、纠错不增加独立根因数。相同 as_of 与事件输入得到同一投影哈希。未来或尚未可用真值不进入历史投影。旧账本和 M0 黄金载荷不因新读取器变化。

## 5. 工作包 C：看见漏检与选择偏差

### 5.1 分阶段保留漏斗损失

新建实验 trace，至少覆盖：L0 未覆盖、L1 丢弃、L2 未报告、评审拒绝、预算未执行、S2 error、确认上报。每阶段记录输入、输出、原因、抽样概率与工件引用。

仅记录已出现的 candidates 还不够：L0 之外的漏洞完全不可见。评测集要提供独立的文件/模块审计抽样框，已知漏洞任务则按金标准回查各层首次漏失位置。

### 5.2 两种独立观察路径

1. **离线金标准任务**：已知漏洞/修复版本对，观察整个漏斗是否发现目标根因；不是只把种子快照交给 verifier 考试。
2. **线上/影子随机审计**：从未被 L0 提名的模块、L1/L2 拒绝项、S2 未选择项分别分层抽样；由独立审核策略或人工检查。审核仍可失败，unknown 不算安全。

推荐 pilot 从总预算中预留 10% 作随机审计，具体比例在 manifest 中锁定。预算不足则减少普通会诊任务，不额外透支。不以严重度排序完全替代随机部分。

抽到任务的概率、无放回规则、层内总量必须可重放。只有标签获取机制与概率支持时才做加权总体估计；若验证缺失仍与难度相关，报告分层结果/范围，不输出伪精确的全仓召回。

### 5.3 防止“只学容易验证的漏洞”

按 family/language/difficulty 报告 S2 成功率与 unknown 比例。verify_error 继续不作为漏洞真假奖励，但应计入 verifier 的可靠性、延迟和成本指标。不能因某类难验证而在报告中消失。

人工复核既抽取 confirmed，也抽取 rejected/inconclusive；否则只能检查已报漏洞的精度，不能检验漏检。

## 6. 工作包 D：S2 判据与负对照

### 6.1 两层结果，不急着扩展公共枚举

保留现有 `VerifyOutcome` 外部三分类；内部报告增加：

- `execution_status`：环境、超时、退出码、实际调用目标、断言输出；
- `claim_validation`：supported / refuted / inconclusive；
- `oracle_kind`、`oracle_version`、`control_results`、`evidence_ref`。

只有执行成功且满足独立验证策略时，才允许 `supported → verified_real`。退出 0、模型自己打印 PASS、日志出现 marker 都不是充分条件。无法形成判据时归 inconclusive，映射 verify_error 并注明具体原因，不能静默当 verified_fp。

`refuted → verified_fp` 要求独立 blocking evidence 明确反驳原主张，并覆盖其输入、环境、权限与可达性前提；仅某次 PoC 没触发、修复版不触发、某条路径不可达都不足以否定原漏洞。无法排除其他满足主张的触发路径时保留 inconclusive。证据引用和范围要通过 SPEC-9/既有 blocking 守卫，不能只凭模型填写了 blocking 字段就授予高可信负标签。

### 6.2 最小可实施判据

先收窄到 Python 命令注入与路径穿越两个已有模板支持面，不宣称覆盖所有安全家族。

- 命令注入：用不可由普通参数回显满足的受控副作用/观察器，并确认触发经过目标代码；目标程序和 PoC 的权限边界、观察文件创建者必须可区分。只让 PoC 自己创建 marker 不算证据。
- 路径穿越：canary 位置在允许根目录之外但仍在沙箱范围内；确认目标接口实际读到该文件，且合法输入/拒绝输入有对照。
- 已知漏洞任务必须跑同一 PoC 的漏洞版与修复版：期望漏洞版成功、修复版不触发同一违规行为。修复版环境失败不算负对照通过。
- 真实未知漏洞不一定有修复版：必须提供替代控制，如阻断输入链/禁用目标 sink 的消融、独立观察器或人工认可的证据。缺控制可保留疑似报告，但不进入高可信学习池。
- “去掉目标调用仍 PASS”“安全 echo 程序打印 payload”“无条件退出 0”“伪造 ASSERT”必须不能获得可信验证。

生成者与验证判据不能完全由同一响应自定。冻结的 harness/观察器负责机械判定，模型只生成驱动；对依赖语言语义的复杂结论仍需人工抽检。

### 6.3 验收集

首批至少包含：漏洞版、修复版、仅回显安全版、不可达 sink、缺依赖、超时、无条件 PASS、目标未调用、真实漏洞但 PoC 无效九类。最后一类必须是 inconclusive，不能判 verified_fp。报告每类结果，不只报总成功率。

process 诊断只运行人工审核的受控合成夹具，且仍零生产写入。**模型生成 PoC 和不可信仓库从首次执行就进入受限 container**，遵守 SPEC-9 红线：网络默认关闭、禁宿主敏感目录/凭据/docker socket 挂载、非特权、只读根、资源限额与超时收割。观察器与目标执行分离，目标/PoC 不得修改观察器或其判定结果。需要网络或特殊权限的实验另行设计隔离与审批，不因难以复现放宽默认。零账本写入只限制业务副作用，不能当作宿主安全隔离。

## 7. 工作包 E：实验体系，而不是继续“重考求过线”

### 7.1 数据与实验登记

拟新增目录：

```text
experiments/design_revision/
  README.md                 # 协议及执行顺序
  manifests/                # 获批且冻结的实验定义
  build_split.py            # 按根因/项目分组切分
  run_profiles.py           # 统一 profile 配对评测
  run_ablation.py           # 同预算策略对照
  analyze.py                # 指标/区间/失败分类
out/design-revision/<experiment_id>/
  manifest.json
  assignments.jsonl
  observations.jsonl
  metrics.json
  report.md
```

以上均为拟新增，本轮只创建本文，不生成空脚本占位。

每个 manifest 锁定：数据哈希、root-cause 分组、开发/验证/保留集、profile 与 prompt 哈希、paper manifest、预算、采样参数、重试规则、停止规则、主要指标、最小有价值效应、统计分析、随机种子、软件版本、允许的联网范围与审批记录。

- 相同源码的变异、同一 CVE 的多个快照、漏洞/修复对必须同组；仓库 fork/相似项目需记录近重复检查。
- 开发集用于调提示词和 harness；验证集选配置；保留集只用于冻结方案的最终评估。
- 用过的保留集不能因失败改名重新当未见集。看过后继续调试，应升级为开发数据，并获取新保留集。
- 变变量名不能证明消除训练污染；模型训练截止点未知时明确标注污染风险。
- 统一评测显式传 paper manifest，不能继续依赖含 agent_id 的 seed 来声称配对。
- 诊断实验与正式资格考试分离；实验新卷不等于获准 re-roll 入编。

### 7.2 E0：仪器与标签可靠性（前置）

目的：先确认评分器、oracle 和题面测量的是想测的东西。

内容：工作包 A 的资格测试、D 的负对照、各家族题目抽样人工复核、漏洞/修复对一致性、指标分母测试。

门禁：确定性反例必须符合预期；发现错误标签时隔离整个关联组，修订版本后重跑受影响对照，不能只删除对某策略不利的样本。

这轮不宣布哪个模型更强，也不调整上线阈值。

### 7.3 E1：专长是否稳定

问题：相同 profile 在前一批任务上的相对优势，能否预测后一批任务？

- 比较 2–3 个实质不同 profile；至少包括当前 flash 与一个更强/不同策略的候选。换供给需批准，不假定旗舰必胜。
- 第一轮限定 2 个支持可靠验证的家族；使用按项目/根因隔离的 A/B 两批。pilot 建议每家族合计至少 20 个独立根因组、跨至少 3 个项目；数量仅用于估计方差，不足以保证统计功效。
- 每个 profile 看相同任务、相同信息与预算；固定重复次数估计采样波动，重复不算新根因。
- 在 A 批选家族优胜配置，同时只用 A 批选定全局固定优胜配置；两者在 B 批开始前冻结，在 B 批检验差异。不得在 B 批事后挑最佳基线再宣称前瞻评估。

主要终点：B 批家族路由相对固定最佳配置的配对质量/成本差异。排名相关性、共同错误率、跨仓一致性为辅助分析。

结果分支：

- 有跨批优势：进入 E2/E3。
- 只有整体强弱、无家族优势：用固定模型级级联，不做细分专员。
- 排名不稳定：合并等价副本，暂停身份级孵化；保留多次采样可能带来的收益作另一问题研究。
- 区间太宽：结论为未知；按预登记规则增样，不能宣称无效或有效。

### 7.4 E2：同预算架构消融

按两层比较，避免把多蜂结构与模型换档混在一起。

**系统比较**：

| 臂 | 内容 | 回答的问题 |
|---|---|---|
| A | 单强模型，可在相同预算内多轮工具调用/自检 | 简单 agentic 基线，而非故意弱化的一次问答 |
| B | 固定级联：cheap 筛选 + 固定深审 + 固定验证 | 级联本身是否划算 |
| C | 固定多蜂 + 会诊 + 验证，无口碑路由 | 多角色/投票是否有增益 |
| D | 与 C 相同供给和工具，使用历史证据路由 | 路由是否有独立增益 |

**机制消融**：只有 C/D 值得继续时，再比较 S1 影子 vs S1 参与能力评分，不一次铺开全部组合。

公平约束：相同任务、可访问信息、工具、安全边界和预算上限。记录实际消耗，同时给出固定预算端点与质量-成本曲线。不能强迫单强模型只用一次调用，却允许蜂群多轮推理。

成本统一分三本账：

1. **每臂部署成本**：该臂实际决策所需侦察/会诊/S2、负对照、重试、探索与随机审计全部计入预算。10% 审计来自该臂预算；若使用公共审计，分摊规则与标签获取权限须在 manifest 固定。
2. **启动学习成本**：历史采集、配置选择、初始探索单列；报告冷启动总成本和按预登记部署任务量摊销的成本，不仅报告学成后的便宜调用。D 不能免费读取其他臂未授权共享的结果。
3. **实验公共测量成本**：盲审、仅用于评分的金标准 oracle、反事实全矩阵额外调用独立列账，不算部署成本，也不向学习器泄漏标签；同时报告整个研究花费。

缓存重放报告实际新增费用与按冻结计价规则还原的逻辑调用成本；比较策略预算时使用后者，不能把缓存命中算免费优势。全矩阵若供学习器选择或更新，则相关观测按该臂的探索成本与可见时间规则入账，不能仍列为免费评分数据。

若 A 使用旗舰而 C 使用全 flash，A/C 只代表两套系统比较，不能用于证明“架构因果优势”；架构比较另做相同供给池对照。

### 7.5 E3：时序学习与在线选择

仅在 E1/E2 支持后实施。把任务按真实或预登记的模拟时间分为 T1/T2/T3：

1. T1 冷启动探索，记录 assignment probability。
2. T2 仅用在 T2 开始前已经 available 的反馈更新；冻结策略作为并行对照。
3. T3 保持规则不变，测试收益是否持续，必要时加入预登记的模型/任务分布漂移。

实验 oracle 可以为评分知道全矩阵答案，但学习器只能看到自己派过任务且已返回的标签。否则是在用全知评估器冒充在线学习。

shadow replay 只能比较已有覆盖的任务，不能把未调用 profile 的反事实结果编造出来。需要反事实时做预算明确的离线全矩阵，或有概率日志的随机对照；不能在覆盖不足时硬算可靠 off-policy 结论。

首版自适应策略保持简单：家族级、按批更新、保留固定探索份额、证据不足回固定基线。不在同一轮加入新的 Thompson/神经 bandit/自动阈值搜索。新旧算法各自作为冻结策略，公平比较。

### 7.6 指标、统计与继续/停止标准

必须同时报告：

- 独立根因级召回、上报 precision、负例拒判；不把 FP 拒判叫 precision。
- 各层漏失、未标注比例、S2 error、基础设施失败。
- 总成本、单位确认漏洞成本、p50/p95 延迟、人工复核分钟数。
- provider 账单/实测 token、名义成本、订阅摊销分列；不得混为同一种实际费用。

known-positive 因调用失败未被发现，仍计入系统端到端召回分母；可以另报“执行成功条件下能力”，但不能以此替代主指标。基础设施重试次数与预算预先固定。

统计以仓库/根因组为单位做配对分析；重复调用先组内汇总，不冒充独立样本。使用分层/聚类 bootstrap 等明确方案；项目数过少时不把 bootstrap 窄区间当总体保证。探索性多指标与主要终点分开，报告原始分子分母。

确认性 manifest 必须指定一个主要质量指标（建议根因召回）及 precision 护栏、标签覆盖规则、单/双侧区间和非劣检验方式。下面的质量提升与成本节省是两种候选成功路径：正式实验只预选一条作为主要路径，另一条作探索性结果；若确需双路径均可放行，预先指定多重检验控制方案。不能试完后选更好看的路径。非劣以配对差异区间下界高于 `-margin` 判断，不仅比较点估计。

**建议的正式门槛，需在确认性实验前批准，不是现有 SPEC：**

- 路由值得上线：相同预算下，主要质量指标提升至少 5 个百分点且差值 95% 区间下界大于 0，同时 precision 不越过预登记非劣界；或质量满足预登记非劣界且成本下降至少 20%，成本比区间上界小于 1。
- 质量非劣界建议先用 2 个百分点讨论，具体必须由误报/漏报成本和 pilot 方差共同确定，不能看完最终结果再改。
- 若要正式声称“至少提升 5 个百分点/节省 20%”，区间也应支持对应幅度；仅点估计达到时，只能声称观察到该幅度。
- 功效不足/区间宽：unknown，不自动放行。根据 pilot 方差、项目内相关性、最小效应确定正式样本量和最大预算。
- 在最大预算内无证据支持 D 优于 C：不部署自适应路由；这不是证明永远无效。
- C 不优于 B：默认退回固定级联；B 不优于 A：保留单强模型与验证工具，停止为蜂群结构额外付费。

禁止以“754 测试通过”“能跑完整链”“有一次分数过线”替代效果门槛。

## 10. 分阶段交付、门禁与投入上限

以下是执行顺序，不是工期承诺。

### P0：修安全边界并冻结测量协议

范围：A + 历史报告勘误 + E 的 manifest/指标定义。

交付：角色资格最小闭环、迁移 dry-run、失败帽测试、明确的实验预算和停止规则。已有 M5 全链仍等待合法 verifier 与可靠判据，不用未过线蜂硬凑。

退出条件：资格门禁通过；能够回答“谁可运行、按哪个 profile、哪张卷、哪个指标”；没有任何新线上调用是未经批准的。

### P1：可信测量最小闭环

范围：D 两家族 oracle + B 只读证据投影 + C 离线漏检 trace + E0。

交付：成对漏洞/修复测试、负对照、金标准数据清单、旧账本不变的投影报告。

退出条件：E0 通过，能够区分脚本失败、主张不成立、无结论；重复和纠错不增加根因数。

### P2：先做专长与固定架构实验

范围：E1 + E2 的 A/B/C；不先做完整新生产数据库和在线 bandit。

交付：跨批专长结果、固定架构成本曲线、逐题失败分析、是否值得进入 P3 的明确决策。

停止条件：没有稳定可用差异且多蜂不优于简单基线，则不开发自适应生产路由。未知时只能按预算内预登记扩样，不能无限实验。

### P3：验证学习收益

范围：E2 的 D + E3；只实现够用的家族级批量更新与概率日志。

交付：冻结路由 vs 学习路由的未来批次对照；严禁未来标签泄漏。

退出条件：满足预登记效果门槛，否则停留影子模式。

### P4：小范围生产

前提：P3 支持且人工批准。限制仓库/家族/总预算，保留固定策略对照流量，监控误报、漏检抽查、成本与资格漂移。触发预登记退化阈值时退回固定级联，不删除实验记录。

只有这时再决定是否恢复自动晋升、衰退、弹性编制与组织展示。新增界面应优先显示证据覆盖与不确定性，而不是先做“专家徽章”。

## 11. 数据迁移、可重放与回退

1. 对生产 SQLite 做一致性备份（SQLite backup API/停写检查点，不仅复制 WAL 模式下单个 db 文件），登记哈希、代码版本和 schema 版本。
2. 在副本上跑迁移 dry-run 与事件重建对账；列出可恢复和不可恢复资格，不猜测补全。
3. 新实验独立 DB/工件目录，默认不导回生产；缓存键包含 profile、prompt、paper、bank、contract、oracle 版本。
4. legacy_v1 重放结果保持原语义；evidence_v2 使用独立版本号和 snapshot，禁止用新公式重解释旧黄金文件。
5. 外部模型响应可缓存重放；“账本重放确定性”与“再次在线调用结果相同”是两回事，报告不得混用。
6. 事件发生时间、反馈可用时间、策略更新时间分别记录；按 as_of 重建不会读到未来反馈。
7. 回退仅切换路由策略/关闭新写入，原始工件和事件保留；安全资格门不允许宽松回退。
8. 升级期间若失败，实验停止、生产保持固定合格策略或暂停；不能拿旧 active 帽当应急豁免。

## 12. 风险与取舍

- **复杂度增长**：新证据体系也可能过度设计。控制方式是先文件投影、两个家族、家族级策略；实验不过，不继续建设生产物化。
- **标注成本**：可靠负例与人工复核昂贵。先小范围 pilot 估算，不以“模型投票当真值”省掉独立标签。
- **样本不足**：真实项目数少，统计不稳定。允许结论 unknown，不把小样本 2/2、40 道真题包装为泛化证明。
- **oracle 覆盖限制**：并非所有漏洞可动态复现。保留静态证据报告与人工路径，不强迫所有家族套同一个 PoC 模板。
- **供应商漂移**：真实服务身份可能不可知。记录不确定性、持续抽检，不能只靠命名版本保证稳定。
- **曝光/污染**：公开 benchmark 与变异数据都可能被模型见过。报告来源、按项目隔离，尽可能引入未公开或新近且可验证的样本，但不宣称绝对无污染。
- **奖励偏差仍存在**：随机抽查改善覆盖，不保证所有漏检可见；输出适用范围与未知部分，不宣称获得完整全仓真值。

## 13. 负责人需要批准的事项

建议分批批准，不要求一次授权所有开发与调用：

1. 批准 P0/P1 设计方向：角色资格门、S1 新策略影子化、证据纠错视图、S2 负对照；旧生产策略除安全门外不默默切换。
2. 批准首批只覆盖两个可验证家族，先不追求全面语言/漏洞覆盖。
3. 确定可用模型、是否允许旗舰/异构供给、token/费用/墙钟/人工复核上限；未批准不调用。
4. 批准 pilot 后再冻结确认性阈值与样本量，而不是按现有 0.8 QC 线推导产品有效。
5. 接受结果分支：若不支持自适应收益，正式收缩到固定级联或单强模型，而不是不断增加补考和机制。

## 14. 最小成功定义

下一阶段的成功不是“更多测试变绿”，也不要求一定证明蜂群优越。

成功应是拿到一份可复核的答案：

> 哪些配置存在可迁移的优势；哪些层确实改善召回/误报/成本；历史反馈在未见任务上增加了多少收益；如果没有收益，能够据此删除哪些复杂度。

只要这四件事说清楚，无论最后保留完整蜂群还是固定级联，项目都在朝可用系统前进。
